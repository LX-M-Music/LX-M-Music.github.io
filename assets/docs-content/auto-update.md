# Windows 自动更新

自动更新由当前运行的**包类型**、**CPU 架构**及 Electron 运行时决定，不能跨类型更新。

## 各类型更新行为

| 当前版本 | 对应附件 | 更新行为 |
| --- | --- | --- |
| 安装版 | `ARCH-Setup.exe` | 校验完整安装包，在原目录静默安装并重启 |
| 便携目录版（green.7z） | `win_ARCH-green.7z`（Win7 为 `win7_ARCH-green.7z`） | 优先**差分更新**；不可用时下载同类型完整压缩包，原目录替换并重启 |
| 单文件版（portable.exe） | `ARCH-portable.exe` | 下载完整单文件程序，退出后替换原 EXE 并从原目录启动 |

- `x64`、`x86`、`arm64` 单独匹配；`x86_64` 合并包只作为安装版与单文件版的低优先级候选
- Win7 运行时只选择带 `win7` 标记的附件
- 没有匹配包时保留手动更新入口

## 差分更新（便携版）

绿色包打包时会从实际应用目录生成两个附加文件：

```text
LX-M.Music-vVERSION-win_x64-green-update.json
LX-M.Music-vVERSION-win_x64-green-update.bin
```

清单包含每个程序文件与数据块的 SHA-256。更新流程：先对数据附件测速，再比对原目录内的数据块，复用相同内容，仅用 HTTP Range 下载变化块，并校验重建后的每个文件。不需要为每个旧版本单独生成补丁；缺少差分附件的历史版本也可正常更新（自动退回完整包）。

## 数据安全

- `portable` 用户数据、歌单、下载文件和个人文件**不在更新范围内**
- 只有上次清单中列出且校验未变化的旧文件才会删除；本地改动过的文件保留
- 更新在独立临时目录完成，原应用运行时不替换文件
- 替换失败或新进程提前退出时自动恢复旧文件并重启旧版

## 更新失败

- 通常是无法访问 GitHub 导致，可手动下载最新安装包覆盖安装
- 绿色版用户建议改用安装版以获得完整的自动更新体验
